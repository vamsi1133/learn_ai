Chapter 1

What is AI Really?

If you have spent eight years building web applications, you already understand more about AI than you think. At its core, AI is about writing programs that improve their behavior based on data rather than explicit instructions. As a JavaScript developer, you have been writing explicit rules your entire career: if (user.age >= 18) allow(). AI flips this: instead of writing rules, you provide examples and let the system discover the rules itself.

Types of AI: A Practical Taxonomy

The term "AI" gets thrown around loosely. Here is a clear breakdown that matters for your work:

Narrow AI (What We Actually Build)

Every AI system you will build as a consultant falls into this category. Narrow AI excels at one specific task: classifying images, generating text, predicting churn, or recommending products. ChatGPT is narrow AI — it is extraordinarily good at text, but it cannot drive a car or fold your laundry.

General AI (AGI — The Distant Goal)

AGI would be a system that can do any intellectual task a human can. We are not there yet. When clients ask about AGI, tell them: "We build solutions with today's narrow AI, which is already powerful enough to transform your business."

Machine Learning vs. Traditional Programming

JS Developer Analogy

Traditional programming is like writing an Express route handler: you define the exact logic. if (request.path === '/users') return getUsers(). You know every branch, every condition.

Machine Learning is like training an autocomplete system: you feed it thousands of examples of inputs and correct outputs, and it learns the mapping function itself. You do not write the rules — the model discovers them from patterns in the data.

Here is the key mental model:

  if (email.includes('meeting') || email.includes('agenda')) return 'work';

Chapter 2

How Machines Learn

In JavaScript, you optimize functions by hand: you tweak parameters, refactor logic, and run tests. Machine learning automates this process. The machine starts with random parameters and iteratively adjusts them until its predictions match the training data. That is literally all learning is: automated parameter optimization.

The Three Paradigms of Machine Learning

1. Supervised Learning: Learning from Labeled Examples

This is the most intuitive form. You give the model input-output pairs, and it learns the mapping function.

JS Developer Analogy

Supervised learning is like writing unit tests first (TDD), then having the computer write the implementation that makes all tests pass. Your labeled data is the test suite.

// Supervised learning: the model learns a function from examples
type TrainingExample = { input: number[]; output: number };

const housePrices: TrainingExample[] = [
  { input: [1200, 2, 1990], output: 250000 },
  { input: [2400, 4, 2010], output: 450000 },
  { input: [800,  1, 1975], output: 180000 },
];

// Simplified gradient descent - how the model "learns"
function trainLinearModel(data: TrainingExample[], lr = 0.0000001, epochs = 1000) {
  let weights = [0, 0, 0];
  let bias = 0;

  for (let epoch = 0; epoch < epochs; epoch++) {
    for (const ex of data) {
      // 1. Predict
      const pred = ex.input.reduce((s, x, i) => s + x * weights[i], bias);
      // 2. Measure error
      const error = pred - ex.output;
      // 3. Adjust weights (gradient descent)
      weights = weights.map((w, i) => w - lr * error * ex.input[i]);
      bias -= lr * error;
    }
  }

  return {
    predict: (input: number[]) =>
      input.reduce((s, x, i) => s + x * weights[i], bias)
  };
}

const model = trainLinearModel(housePrices);
console.log(model.predict([1800, 3, 2005])); // ~$350,000

2. Unsupervised Learning: Finding Hidden Patterns

No labels here. The model discovers structure on its own. Common uses: clustering customers into segments, detecting anomalies, dimensionality reduction.

// Conceptual: K-means clustering in TypeScript
interface UserBehavior {
  avgSessionMinutes: number;
  purchasesPerMonth: number;
  supportTickets: number;
}

function distance(a: UserBehavior, b: UserBehavior): number {
  return Math.sqrt(
    (a.avgSessionMinutes - b.avgSessionMinutes) ** 2 +
    (a.purchasesPerMonth - b.purchasesPerMonth) ** 2 +
    (a.supportTickets - b.supportTickets) ** 2
  );
}

// K-means finds natural groupings without you defining them
// Result might reveal: "power users", "casual browsers", "at-risk churners"
// You never told the model these categories exist - it found them

3. Reinforcement Learning: Learning by Trial and Error

The model takes actions in an environment and receives rewards or penalties. It learns a strategy (policy) that maximizes long-term reward. This is less common in web dev but powers game-playing AIs and robotics.

// Conceptual: RL for auto-scaling decisions
type Action = 'scale_up' | 'scale_down' | 'do_nothing';

class AutoScaleAgent {
  // The agent observes: CPU %, memory %, request rate, error rate
  // It takes an action: scale up, down, or nothing
  // Reward: +1 for low latency, -1 for errors, -0.5 for wasted resources
  // Over time it learns: "high CPU + rising requests = scale up"

  chooseAction(state: { cpu: number; memory: number; rps: number }): Action {
    // After training, the agent's learned policy might look like:
    if (state.cpu > 80 && state.rps > 1000) return 'scale_up';
    if (state.cpu < 20 && state.rps < 100) return 'scale_down';
    return 'do_nothing';
    // But RL discovers this policy automatically through trial and error!
  }
}

The Training Loop: Predict, Measure, Adjust

Every ML training process follows the same loop. It maps cleanly to TDD:

  1. Predict — run the function with current parameters (like running a test)
  2. Measure error — compare prediction to correct answer (test assertion failing)
  3. Adjust — tweak parameters to reduce error (fixing the implementation)
  4. Repeat — until error is minimized (all tests pass)

The "error" is formally called a loss function. The adjustment process is gradient descent. The gradient tells you which direction to adjust each parameter — the mathematical equivalent of reading a test failure message to know what to fix.

Overfitting vs. Generalization

Overfitting is the ML equivalent of hardcoding return values to pass specific tests:

// Overfit: memorized training data, useless on new inputs
function predictOverfit(sqft: number): number {
  if (sqft === 1200) return 250000;
  if (sqft === 2400) return 450000;
  return 0; // no idea for unseen inputs!
}

// Generalized: learned the underlying relationship
function predictGeneralized(sqft: number): number {
  return sqft * 187.5 + 25000; // works on any input
}

To prevent overfitting: use more training data, keep models simpler, and always test on data the model has never seen (the test set). This is why ML teams split data into training, validation, and test sets — exactly like separating unit tests from integration tests.

Key Takeaway

Machine learning is automated function optimization. Supervised learning uses labeled examples (TDD). Unsupervised learning finds hidden structure. Reinforcement learning uses trial and error. The core loop — predict, measure error, adjust — is universal. Overfitting is the #1 trap: always evaluate on unseen data.

Chapter 3

Neural Networks Demystified

Neural networks sound exotic, but if you have ever chained .map() and .filter() calls in JavaScript, you already understand the core concept. A neural network is a pipeline of transform functions where each step takes input, applies a weighted transformation, and passes the result to the next step. The "learning" part is automatically tuning the weights until the pipeline produces correct outputs.

A Neuron is Just a Weighted Sum + Activation

A single artificial neuron does three things:

  1. Takes multiple inputs and multiplies each by a weight
  2. Sums the weighted inputs plus a bias term
  3. Passes the sum through an activation function
// A single neuron in TypeScript
function neuron(
  inputs: number[],
  weights: number[],
  bias: number,
  activation: (x: number) => number
): number {
  // Step 1 & 2: weighted sum
  const weightedSum = inputs.reduce(
    (sum, input, i) => sum + input * weights[i], bias
  );
  // Step 3: activation function
  return activation(weightedSum);
}

// Common activation functions
const relu = (x: number) => Math.max(0, x);        // Most popular: if positive keep it, else 0
const sigmoid = (x: number) => 1 / (1 + Math.exp(-x)); // Squashes to 0-1 (like probability)
const tanh = (x: number) => Math.tanh(x);             // Squashes to -1 to 1

// Example: a neuron deciding if an email is spam
const spamScore = neuron(
  [0.9, 0.1, 0.8],  // features: hasSpamWords, isFromContact, hasLinks
  [0.7, -0.5, 0.3], // learned weights
  -0.2,              // bias
  sigmoid              // output between 0 and 1
);
// spamScore = sigmoid(0.9*0.7 + 0.1*(-0.5) + 0.8*0.3 + (-0.2))
// = sigmoid(0.63 - 0.05 + 0.24 - 0.2) = sigmoid(0.62) = 0.65
// 65% chance of spam

JS Developer Analogy

A neuron is like a .reduce() call followed by a .map() with a clamping function. The weights are like configuration values, and the activation function is like a normalizer that keeps the output in a useful range.

Layers: Stacking Neurons into Pipelines

A single neuron can only learn linear relationships (straight lines). To learn complex patterns, you stack neurons into layers, and layers into a network. This is exactly like building a data processing pipeline:

// Neural network as a data pipeline
class NeuralNetwork {
  layers: Layer[];

  constructor(layerSizes: number[]) {
    this.layers = [];
    for (let i = 1; i < layerSizes.length; i++) {
      this.layers.push(new Layer(layerSizes[i - 1], layerSizes[i]));
    }
  }

  forward(input: number[]): number[] {
    // Data flows through each layer sequentially
    // Just like: input.map(layer1).map(layer2).map(layer3)
    let current = input;
    for (const layer of this.layers) {
      current = layer.forward(current);
    }
    return current;
  }
}

class Layer {
  weights: number[][];
  biases: number[];

  constructor(inputSize: number, outputSize: number) {
    // Initialize with small random weights
    this.weights = Array.from({ length: outputSize }, () =>
      Array.from({ length: inputSize }, () => Math.random() * 0.2 - 0.1)
    );
    this.biases = new Array(outputSize).fill(0);
  }

  forward(input: number[]): number[] {
    return this.weights.map((neuronWeights, i) => {
      const sum = neuronWeights.reduce((s, w, j) => s + w * input[j], this.biases[i]);
      return Math.max(0, sum); // ReLU activation
    });
  }
}

// Create a network: 3 inputs -> 4 hidden -> 4 hidden -> 1 output
const net = new NeuralNetwork([3, 4, 4, 1]);
const output = net.forward([0.5, 0.8, 0.2]);

Why Depth Matters: Feature Hierarchies

Deep networks (many layers) learn features at increasing levels of abstraction. In image recognition:

  • Layer 1 detects edges (like CSS border detection)
  • Layer 2 combines edges into shapes (corners, curves)
  • Layer 3 combines shapes into parts (eyes, wheels)
  • Layer 4 combines parts into objects (faces, cars)

For text (LLMs), it is similar: early layers learn grammar and word relationships, middle layers learn semantic meaning, and later layers learn reasoning patterns.

Activation Functions: Why Non-Linearity Matters

Without activation functions, stacking layers is pointless — multiple linear transforms collapse into one linear transform. Activation functions introduce non-linearity, letting the network learn curves instead of just straight lines.

// Without activation: layers collapse (useless)
// layer1: y = 2x + 1
// layer2: y = 3x + 5
// combined: y = 3(2x + 1) + 5 = 6x + 8  -- still linear!

// With ReLU activation: layers build complexity
// layer1: y = relu(2x + 1)  -- creates a "bend" at x = -0.5
// layer2: y = relu(3*layer1 + 5)  -- adds another bend
// Now the network can approximate ANY function!

// Visualization: activation functions in TypeScript
const activations = {
  relu:    (x: number) => Math.max(0, x),
  sigmoid: (x: number) => 1 / (1 + Math.exp(-x)),
  tanh:    (x: number) => Math.tanh(x),
  gelu:    (x: number) => // Used in transformers (GPT, Claude)
    x * 0.5 * (1 + Math.tanh(Math.sqrt(2 / Math.PI) * (x + 0.044715 * x ** 3))),
};

Backpropagation: How the Network Learns

Backpropagation is the algorithm that computes how to adjust every weight in the network to reduce the error. Think of it like this: if your Express app returns a wrong response, you trace back through middleware to find which handler caused the bug. Backpropagation does this automatically with calculus (the chain rule).

// Backpropagation conceptually (simplified)
function trainNetwork(
  net: NeuralNetwork,
  data: { input: number[]; expected: number[] }[],
  learningRate: number,
  epochs: number
) {
  for (let epoch = 0; epoch < epochs; epoch++) {
    let totalLoss = 0;

    for (const { input, expected } of data) {
      // Forward pass: compute prediction
      const output = net.forward(input);

      // Compute loss (mean squared error)
      const loss = expected.reduce(
        (sum, exp, i) => sum + (output[i] - exp) ** 2, 0
      ) / expected.length;
      totalLoss += loss;

      // Backward pass: compute gradients layer by layer (chain rule)
      // Then adjust each weight: weight -= learningRate * gradient
      // This is the "tracing back through middleware" step
      net.backward(expected, learningRate);
    }

    if (epoch % 100 === 0) {
      console.log(`Epoch ${epoch}: loss = ${totalLoss / data.length}`);
    }
  }
}

Chapter 4

How LLMs Work

Large Language Models are the technology behind ChatGPT, Claude, and every text-generating AI. As a developer who will build on top of these models daily, understanding their internals gives you a massive edge. You will know why certain prompts work better, why the model hallucinates, and how to work within its constraints. Let us open the black box.

The Transformer Architecture

The Transformer, introduced in the 2017 paper "Attention Is All You Need," is the architecture that powers every modern LLM. Before Transformers, language models processed text sequentially (one word at a time, like a for loop). Transformers process all words in parallel (like Promise.all()), which is dramatically faster and captures long-range relationships.

JS Developer Analogy

Imagine processing an array of words. An RNN is like array.reduce() — each word depends on the previous computation. A Transformer is like array.map() where each element can "look at" every other element simultaneously. This parallelism is why Transformers can be trained on massive datasets.

Tokenization: How Text Becomes Numbers

LLMs do not see text — they see numbers. Tokenization splits text into subword chunks and maps each to an integer. Understanding tokenization is critical for cost estimation and prompt design.

// Conceptual tokenizer (real ones use BPE or SentencePiece)
class SimpleTokenizer {
  private vocab: Map<string, number> = new Map();
  private nextId = 0;

  tokenize(text: string): number[] {
    // Real tokenizers split "unbelievable" into ["un", "believ", "able"]
    // This lets the model understand prefixes/suffixes it has seen
    const words = text.toLowerCase().split(/\s+/);
    return words.map(word => {
      if (!this.vocab.has(word)) {
        this.vocab.set(word, this.nextId++);
      }
      return this.vocab.get(word)!;
    });
  }
}

// Key facts about real tokenization:
// - GPT-4 uses ~100,000 token vocabulary
// - "Hello world" = 2 tokens, but "Pneumonoultramicroscopicsilicovolcanoconiosis" = 9 tokens
// - Code is token-expensive: each bracket, keyword, symbol is a token
// - Average English: ~1 token per 4 characters, or ~0.75 tokens per word
// - This directly affects cost (you pay per token) and context limits

The Attention Mechanism: The Core Innovation

Attention lets each token "look at" every other token and decide which ones are relevant. When the model processes the word "it" in "The cat sat on the mat because it was tired," attention helps it figure out that "it" refers to "cat" not "mat."

// Simplified self-attention in TypeScript
function selfAttention(
  tokens: number[][]  // each token is a vector of numbers (embedding)
): number[][] {
  const d = tokens[0].length; // embedding dimension
  const scale = Math.sqrt(d);

  return tokens.map((query, i) => {
    // For each token, compute how much to "attend" to every other token
    const scores = tokens.map(key =>
      dotProduct(query, key) / scale  // higher score = more relevant
    );

    // Softmax: convert scores to probabilities (sum to 1)
    const weights = softmax(scores);

    // Weighted sum: blend all tokens based on relevance
    return tokens[0].map((_, dim) =>
      tokens.reduce((sum, tok, j) => sum + weights[j] * tok[dim], 0)
    );
  });
}

function dotProduct(a: number[], b: number[]): number {
  return a.reduce((sum, val, i) => sum + val * b[i], 0);
}

function softmax(values: number[]): number[] {
  const max = Math.max(...values);
  const exps = values.map(v => Math.exp(v - max));
  const sum = exps.reduce((s, e) => s + e, 0);
  return exps.map(e => e / sum);
}

Real Transformers use multi-head attention — they run multiple attention computations in parallel, each focusing on different types of relationships (syntax, semantics, coreference). Think of it as having multiple .map() passes, each with a different lens.

// Context window management is a real engineering concern
interface ContextBudget {
  totalTokens: number;
  systemPrompt: number;   // reserved for instructions
  retrievedDocs: number;  // RAG context
  conversation: number;   // chat history

function planContextBudget(model: string): ContextBudget {
  const limits: Record<string, number> = {
    'gpt-4o': 128000,
    'claude-sonnet-4-20250514': 200000,
  };
  const total = limits[model] ?? 8000;
  return {
    totalTokens: total,
    systemPrompt: Math.min(2000, total * 0.05),
    retrievedDocs: total * 0.5,   // half the budget for RAG docs
    conversation: total * 0.3,    // 30% for history
    outputReserve: total * 0.15,  // 15% for the response
  };
}

Temperature and Sampling: Controlling Randomness

When an LLM generates text, it predicts a probability distribution over the entire vocabulary for the next token. Temperature controls how "creative" vs "deterministic" the output is.

// Temperature affects the probability distribution
function applyTemperature(logits: number[], temperature: number): number[] {
  // temperature = 0: always pick the most likely token (deterministic)
  // temperature = 1: sample naturally from the distribution
  // temperature = 2: flatten the distribution (more random/creative)
  const scaled = logits.map(l => l / temperature);
  return softmax(scaled);
}

const temperatureGuide = {
  0.0: 'Deterministic: code generation, data extraction, classification',
  0.3: 'Low creativity: professional writing, summaries, analysis',
  0.7: 'Balanced: general conversation, explanations',
  1.0: 'Creative: brainstorming, fiction, marketing copy',
  1.5: 'High randomness: wild ideas, but higher hallucination risk',
};

How LLM Training Actually Works

LLMs are trained in two phases:

  1. Pre-training: The model reads the entire internet (billions of pages) and learns to predict the next token. This gives it general knowledge of language, facts, code, and reasoning patterns. This costs millions of dollars in compute.
  2. Fine-tuning / RLHF: The model is refined on human feedback. Humans rate responses, and the model learns to produce outputs humans prefer. This is what makes ChatGPT helpful rather than just autocomplete on steroids.

Why LLMs Hallucinate

LLMs generate the most probable next token, not the most truthful. They have no concept of truth — they are pattern-matching against their training data. If a plausible-sounding but incorrect answer matches common patterns, the model will generate it confidently. This is why verification, RAG (Chapter 8), and guardrails (Chapter 23) are critical in production systems.

Key Takeaway

LLMs are Transformer neural networks trained to predict the next token. Key concepts: tokenization (text to numbers), attention (relating tokens to each other), context windows (hard memory limit), and temperature (creativity vs determinism). Understanding these mechanics helps you write better prompts, estimate costs, and debug unexpected behavior. The model does not "understand" in a human sense — it is extremely sophisticated pattern matching.

  provider: Provider;
  model?: string;
  systemPrompt?: string;
  temperature?: number;
  maxTokens?: number;
}

  anthropic: { model: 'claude-sonnet-4-20250514' },
  openai:    { model: 'gpt-4o' },
};

async function chat(message: string, opts: ChatOptions): Promise<string> {
  const model = opts.model ?? defaults[opts.provider].model;

  if (opts.provider === 'anthropic') {
    const client = new Anthropic();
    const res = await client.messages.create({
      model,
      max_tokens: opts.maxTokens ?? 1024,
      system: opts.systemPrompt,
      messages: [{ role: 'user', content: message }],
    });
    return res.content.find(b => b.type === 'text')?.text ?? '';
  }

  const client = new OpenAI();
  const messages: OpenAI.ChatCompletionMessageParam[] = [];
  if (opts.systemPrompt) messages.push({ role: 'system', content: opts.systemPrompt });
  messages.push({ role: 'user', content: message });

  const res = await client.chat.completions.create({
    model,
    messages,
    max_tokens: opts.maxTokens ?? 1024,
    temperature: opts.temperature ?? 0.7,
  });
  return res.choices[0].message.content ?? '';
}

Embeddings & Vector Databases

Embeddings are the bridge between human language and mathematical operations. They convert text into arrays of numbers (vectors) where similar meanings end up close together in vector space. This is the foundation for semantic search, recommendations, and RAG (next chapter).

What Are Embeddings?

JS Developer Analogy

Imagine you have a Map<string, number[]> where every word or sentence maps to a coordinate in 1,536-dimensional space. Words with similar meanings have similar coordinates. "happy" and "joyful" are neighbors; "happy" and "database" are far apart. You can literally do king - man + woman = queen with vector math.

// Getting embeddings from OpenAI
import OpenAI from 'openai';

const openai = new OpenAI();

async function getEmbedding(text: string): Promise<number[]> {
  const response = await openai.embeddings.create({
    model: 'text-embedding-3-small',  // 1,536 dimensions, cheap
    input: text,
  });
  return response.data[0].embedding;  // number[] of length 1536
}

// Cosine similarity: measure how similar two embeddings are
function cosineSimilarity(a: number[], b: number[]): number {
  let dotProduct = 0, normA = 0, normB = 0;
  for (let i = 0; i < a.length; i++) {
    dotProduct += a[i] * b[i];
    normA += a[i] * a[i];
    normB += b[i] * b[i];
  }
  return dotProduct / (Math.sqrt(normA) * Math.sqrt(normB));
}

// Demo: semantic similarity
const e1 = await getEmbedding('The cat sat on the mat');
const e2 = await getEmbedding('A kitten rested on the rug');
const e3 = await getEmbedding('SELECT * FROM users WHERE id = 1');

console.log(cosineSimilarity(e1, e2)); // ~0.92 (very similar)
console.log(cosineSimilarity(e1, e3)); // ~0.15 (very different)

Practical Example: Semantic Search for a Knowledge Base

// Full semantic search pipeline
import OpenAI from 'openai';

interface Document {
  id: string;
  content: string;
  embedding?: number[];
  metadata: Record<string, string>;
}

class SimpleVectorStore {
  private docs: Document[] = [];
  private openai = new OpenAI();

  async addDocument(doc: Omit<Document, 'embedding'>) {
    const embedding = await this.embed(doc.content);
    this.docs.push({ ...doc, embedding });
  }

  async search(query: string, topK = 3): Promise<Document[]> {
    const queryEmb = await this.embed(query);
    return this.docs
      .map(doc => ({
        doc,
        score: cosineSimilarity(queryEmb, doc.embedding!),
      }))
      .sort((a, b) => b.score - a.score)
      .slice(0, topK)
      .map(r => r.doc);
  }

  private async embed(text: string): Promise<number[]> {
    const res = await this.openai.embeddings.create({
      model: 'text-embedding-3-small',
      input: text,
    });
    return res.data[0].embedding;
  }
}

Embeddings turn text into numbers where similar meanings are numerically close. Vector databases let you search by meaning instead of keywords. In production, consider Pinecone or pgvector depending on your stack.

RAG — Making LLMs Know Your Data

Retrieval-Augmented Generation (RAG) is the most important pattern in applied AI. It solves the fundamental problem: LLMs know about the internet, but they do not know about your company's data, docs, or codebase. RAG retrieves relevant context from your data and injects it into the prompt before the LLM generates a response.

The RAG Pipeline

JS Developer Analogy

RAG is like middleware for LLMs. Before the request hits the model, your middleware fetches relevant data from your database and attaches it to the request context. The model then answers based on your data, not just its training data. Think: Express middleware that enriches req.context before the handler runs.

// The complete RAG pipeline
import Anthropic from '@anthropic-ai/sdk';

interface RAGConfig {
  chunkSize: number;      // characters per chunk
  chunkOverlap: number;   // overlap between chunks
  topK: number;           // number of chunks to retrieve
  similarityThreshold: number; // minimum relevance score
}

class RAGPipeline {
  private vectorStore: SimpleVectorStore;
  private anthropic = new Anthropic();
  private config: RAGConfig;

  constructor(config: Partial<RAGConfig> = {}) {
    this.config = {
      chunkSize: 500,
      chunkOverlap: 50,
      topK: 5,
      similarityThreshold: 0.7,
      ...config,
    };
    this.vectorStore = new SimpleVectorStore();
  }

  // Step 1: Ingest documents (run once, or on update)
  async ingest(documents: { id: string; content: string; source: string }[]) {
    for (const doc of documents) {
      const chunks = this.chunkText(doc.content);
      for (let i = 0; i < chunks.length; i++) {
        await this.vectorStore.addDocument({
          id: `${doc.id}-chunk-${i}`,
          content: chunks[i],
          metadata: { source: doc.source, chunkIndex: String(i) },
        });
      }
    }
  }

  // Step 2: Query with RAG
  async query(question: string): Promise<string> {
    // 2a: Retrieve relevant chunks
    const relevantDocs = await this.vectorStore.search(
      question, this.config.topK
    );

    // 2b: Build the prompt with retrieved context
    const context = relevantDocs
      .map((doc, i) => `[Source ${i + 1}: ${doc.metadata.source}]\n${doc.content}`)
      .join('\n\n');

    // 2c: Generate answer grounded in retrieved context
    const response = await this.anthropic.messages.create({
      model: 'claude-sonnet-4-20250514',
      max_tokens: 1024,
      system: `Answer questions based ONLY on the provided context.
If the context does not contain the answer, say "I don't have enough information to answer that."
Always cite which source(s) you used.`,
      messages: [{
        role: 'user',
        content: `Context:\n${context}\n\nQuestion: ${question}`,
      }],
    });

    return response.content[0].type === 'text' ? response.content[0].text : '';
  }

  // Chunking strategy: split text into overlapping chunks
  private chunkText(text: string): string[] {
    const chunks: string[] = [];
    const { chunkSize, chunkOverlap } = this.config;
    let start = 0;
    while (start < text.length) {
      let end = Math.min(start + chunkSize, text.length);
      // Try to break at a sentence boundary
      if (end < text.length) {
        const lastPeriod = text.lastIndexOf('.', end);
        if (lastPeriod > start + chunkSize * 0.5) end = lastPeriod + 1;
      }
      chunks.push(text.slice(start, end).trim());
      start = end - chunkOverlap;
    }
    return chunks;
  }
}

// Recursive chunking for Markdown documentation
function chunkMarkdown(markdown: string, maxSize = 800): string[] {
  // Split by headings first
  const sections = markdown.split(/(?=^#{1,3} )/m);
  const chunks: string[] = [];

  for (const section of sections) {
    if (section.length <= maxSize) {
      chunks.push(section.trim());
    } else {
      // Section too big: split by paragraphs
      const paragraphs = section.split(/\n\n+/);
      let current = '';
      for (const para of paragraphs) {
        if (current.length + para.length > maxSize && current) {
          chunks.push(current.trim());
          current = '';
        }
        current += para + '\n\n';
      }
      if (current.trim()) chunks.push(current.trim());
    }
  }
  return chunks;
}

RAG = Retrieve relevant context + Augment the prompt + Generate a grounded response. It is the standard pattern for making LLMs work with private data. The quality depends heavily on chunking strategy and retrieval accuracy. Start simple (fixed-size chunks, cosine similarity search), then optimize based on what users actually ask. Always instruct the model to cite sources and admit when it does not know.

What Are AI Agents?

An AI agent is an LLM that can take actions, not just generate text. While a chatbot answers questions, an agent can search databases, call APIs, modify files, and make decisions in a loop. The core pattern is simple: Think → Act → Observe → Repeat.

The Agent Loop

JS Developer Analogy

An agent is like a while loop with an LLM as the control flow. Imagine writing a program where the loop condition and the function calls inside are decided by the LLM at runtime. The agent is an event loop: receive input, decide what function to call, observe the result, decide the next step.

// The fundamental agent loop
interface Tool {
  name: string;
  description: string;
  parameters: Record<string, unknown>;
  execute: (params: Record<string, unknown>) => Promise<string>;
}

interface AgentStep {
  thought: string;
  action?: { tool: string; params: Record<string, unknown> };
  observation?: string;
  finalAnswer?: string;
}

async function agentLoop(
  goal: string,
  tools: Tool[],
  maxSteps = 10
): Promise<string> {
  const steps: AgentStep[] = [];

  for (let i = 0; i < maxSteps; i++) {
    // THINK: Ask the LLM what to do next
    const decision = await askLLM(goal, tools, steps);

    if (decision.finalAnswer) {
      return decision.finalAnswer; // Done!
    }

    if (decision.action) {
      // ACT: Execute the chosen tool
      const tool = tools.find(t => t.name === decision.action!.tool);
      if (!tool) throw new Error(`Unknown tool: ${decision.action.tool}`);

      // OBSERVE: Get the result
      const observation = await tool.execute(decision.action.params);
      decision.observation = observation;
    }

    steps.push(decision);
  }

  return 'Agent reached maximum steps without a final answer.';
}

import { join, relative } from 'path';

const client = new Anthropic();

// Define the tools the agent can use
const tools: Anthropic.Tool[] = [
  {
    name: 'list_files',
    description: 'List files in a directory. Returns file names and sizes.',
    input_schema: {
      type: 'object',
      properties: {
        path: { type: 'string', description: 'Directory path relative to project root' },
        pattern: { type: 'string', description: 'Optional glob pattern filter (e.g., "*.ts")' },

  },
  {
    name: 'read_file',
    description: 'Read the contents of a file.',
    input_schema: {
      type: 'object',
      properties: {
        path: { type: 'string', description: 'File path relative to project root' },
      },
      required: ['path'],
    },
  },

    name: 'search_code',
    description: 'Search for a text pattern across all files in the project.',
    input_schema: {
      type: 'object',
      properties: {
        pattern: { type: 'string', description: 'Text or regex pattern to search for' },
        fileType: { type: 'string', description: 'File extension to filter (e.g., "ts")' },
      },
      required: ['pattern'],
    },
  },
];

// Tool implementations
async function executeTool(name: string, input: any, projectRoot: string): Promise<string> {
  switch (name) {
    case 'list_files': {
      const dirPath = join(projectRoot, input.path);
      const entries = await readdir(dirPath, { withFileTypes: true });
      const results = await Promise.all(
        entries.map(async e => {
          const s = await stat(join(dirPath, e.name));
          return `${e.isDirectory() ? '[DIR]' : '[FILE]'} ${e.name} (${s.size} bytes)`;
        })
      );
      return results.join('\n');
    }
    case 'read_file': {
      const content = await readFile(join(projectRoot, input.path), 'utf-8');
      return content.slice(0, 5000); // Truncate large files
    }
    case 'search_code': {
      // Simple recursive search
      const matches: string[] = [];
      async function search(dir: string) {
        const entries = await readdir(dir, { withFileTypes: true });
        for (const e of entries) {
          if (e.name.startsWith('.') || e.name === 'node_modules') continue;
          const fullPath = join(dir, e.name);
          if (e.isDirectory()) { await search(fullPath); }
          else if (!input.fileType || e.name.endsWith(`.${input.fileType}`)) {
            const content = await readFile(fullPath, 'utf-8');
            const lines = content.split('\n');
            lines.forEach((line, idx) => {
              if (line.includes(input.pattern)) {
                matches.push(`${relative(projectRoot, fullPath)}:${idx + 1}: ${line.trim()}`);
              }
            });
          }
        }
      }
      await search(projectRoot);
      return matches.slice(0, 20).join('\n') || 'No matches found';
    }
    default:
      return `Unknown tool: ${name}`;
  }
}

// The agent loop
async function codeExplorerAgent(question: string, projectRoot: string): Promise<string> {
  let messages: Anthropic.MessageParam[] = [
    { role: 'user', content: question },
  ];

  for (let step = 0; step < 10; step++) {
    const response = await client.messages.create({
      model: 'claude-sonnet-4-20250514',
      max_tokens: 4096,
      system: `You are a code exploration agent. Use the provided tools to
investigate the codebase and answer the user's question thoroughly.
Always look at actual code before answering - never guess.`,
      tools,
      messages,
    });

    // Check if the model wants to use tools
    const toolUseBlocks = response.content.filter(b => b.type === 'tool_use');

    if (toolUseBlocks.length === 0) {
      // No tool use = final answer
      const textBlock = response.content.find(b => b.type === 'text');
      return textBlock?.text ?? 'No answer generated';
    }

    // Execute all tool calls and send results back
    messages.push({ role: 'assistant', content: response.content });

    const toolResults: Anthropic.ToolResultBlockParam[] = [];
    for (const block of toolUseBlocks) {
      if (block.type === 'tool_use') {
        console.log(`  [Agent] Using tool: ${block.name}`);
        const result = await executeTool(block.name, block.input, projectRoot);
        toolResults.push({
          type: 'tool_result',
          tool_use_id: block.id,
          content: result,
        });
      }
    }

    messages.push({ role: 'user', content: toolResults });
  }

  return 'Agent exceeded maximum steps.';
}

Error Handling and Safety

// Production-ready tool execution with safety
async function safeExecuteTool(
  name: string,
  input: any,
  projectRoot: string
): Promise<string> {
  try {
    // Security: prevent path traversal
    if (input.path && (input.path.includes('..') || input.path.startsWith('/'))) {
      return 'Error: path traversal not allowed';
    }
    // Timeout protection
    const result = await Promise.race([
      executeTool(name, input, projectRoot),
      new Promise<string>((_, reject) =>
        setTimeout(() => reject(new Error('Tool timeout')), 10000)
      ),
    ]);
    return result;
  } catch (error) {
    return `Error executing ${name}: ${error instanceof Error ? error.message : 'unknown error'}`;
  }
}

Key Takeaway

Building an agent is about three things: defining tools (with clear descriptions the LLM can understand), implementing a loop that alternates between LLM decisions and tool execution, and adding safety guardrails (path traversal prevention, timeouts, max steps). The LLM's tool descriptions are as important as API docs — unclear descriptions lead to wrong tool choices.

Multi-Agent Systems

A single agent has limits: one system prompt, one set of tools, one context. Multi-agent systems solve complex problems by having specialized agents collaborate. Think of it like a microservices architecture, but for AI: each agent is an expert in one domain.

The Orchestrator Pattern

The most practical pattern: one "manager" agent receives the task and delegates to specialist agents.

// Multi-agent orchestrator
interface Agent {
  name: string;
  description: string;
  systemPrompt: string;
  tools: Anthropic.Tool[];
  run: (task: string) => Promise<string>;
}

class OrchestratorAgent {
  private specialists: Agent[];
  private client = new Anthropic();

  constructor(specialists: Agent[]) {
    this.specialists = specialists;
  }

  async run(task: string): Promise<string> {
    // Step 1: Plan - break the task into subtasks
    const plan = await this.createPlan(task);
    console.log('Plan:', plan);

    // Step 2: Execute - delegate each subtask to the right specialist
    const results: { agent: string; task: string; result: string }[] = [];

    for (const subtask of plan.subtasks) {
      const specialist = this.specialists.find(s => s.name === subtask.agent);
      if (!specialist) continue;
      console.log(`  Delegating to ${specialist.name}: ${subtask.description}`);
      const result = await specialist.run(subtask.description);
      results.push({ agent: specialist.name, task: subtask.description, result });
    }

    // Step 3: Synthesize - combine results into final answer
    return await this.synthesize(task, results);
  }

  private async createPlan(task: string) {
    const agentList = this.specialists
      .map(s => `- ${s.name}: ${s.description}`)
      .join('\n');

    const response = await this.client.messages.create({
      model: 'claude-sonnet-4-20250514',
      max_tokens: 1024,
      system: `You are a task planner. Break down tasks and assign to specialists.
Available specialists:\n${agentList}\n
Return JSON: { "subtasks": [{ "agent": "name", "description": "what to do" }] }`,
      messages: [{ role: 'user', content: task }],
    });

    const text = response.content[0].type === 'text' ? response.content[0].text : '{}';
    return JSON.parse(text);
  }

  private async synthesize(
    originalTask: string,
    results: { agent: string; task: string; result: string }[]
  ): Promise<string> {
    const context = results
      .map(r => `[${r.agent}] Task: ${r.task}\nResult: ${r.result}`)
      .join('\n\n');

    const response = await this.client.messages.create({
      model: 'claude-sonnet-4-20250514',
      max_tokens: 2048,
      system: 'Synthesize the specialist results into a coherent final answer.',
      messages: [{
        role: 'user',
        content: `Original task: ${originalTask}\n\nSpecialist results:\n${context}`,
      }],
    });

    return response.content[0].type === 'text' ? response.content[0].text : '';
  }
}

Agent Handoff Pattern

Instead of the orchestrator calling agents, agents can hand off to each other when they realize a task needs a different expert:

// Agent handoff: agents transfer control to each other
interface HandoffResult {
  type: 'answer' | 'handoff';
  content: string;
  handoffTo?: string;
  handoffReason?: string;
}

async function runWithHandoffs(
  task: string,
  agents: Map<string, Agent>,
  startAgent: string,
  maxHandoffs = 5
): Promise<string> {
  let currentAgent = startAgent;
  let currentTask = task;

  for (let i = 0; i < maxHandoffs; i++) {
    const agent = agents.get(currentAgent);
    if (!agent) throw new Error(`No agent: ${currentAgent}`);

    console.log(`[${currentAgent}] Processing: ${currentTask.slice(0, 80)}...`);
    const result: HandoffResult = JSON.parse(await agent.run(currentTask));

    if (result.type === 'answer') return result.content;
    if (result.type === 'handoff' && result.handoffTo) {
      console.log(`  Handing off to ${result.handoffTo}: ${result.handoffReason}`);
      currentAgent = result.handoffTo;
      currentTask = result.content;
    }
  }
  return 'Maximum handoffs reached';
}

Key Takeaway

Multi-agent systems decompose complex tasks among specialists. The orchestrator pattern (a planner that delegates to experts) is the most practical starting point. Agent handoffs let agents transfer control when they hit their limits. Start with 2-3 agents and add more only when you see clear domain boundaries. Over-engineering multi-agent systems is common — a single well-prompted agent often beats a poorly designed multi-agent system.

Intent Classification Pipeline

// Multi-stage support automation pipeline
import Anthropic from '@anthropic-ai/sdk';
import { z } from 'zod';

const SupportIntent = z.object({
  intent: z.enum([
    'billing_inquiry', 'technical_issue', 'account_access',
    'feature_request', 'cancellation', 'general_question',
    'complaint', 'praise',
  ]),
  urgency: z.enum(['critical', 'high', 'medium', 'low']),
  sentiment: z.enum(['angry', 'frustrated', 'neutral', 'positive']),
  canAutoResolve: z.boolean(),
  escalationReason: z.string().optional(),
});

class SupportAutomation {
  private client = new Anthropic();
  private knowledgeBase: RAGPipeline;

  async handleTicket(message: string, customerContext: {
    name: string; plan: string; accountAge: string;
  }): Promise<{ response: string; escalated: boolean; intent: string }> {
    // Step 1: Classify intent and urgency
    const classification = await this.classifyIntent(message);

    // Step 2: Check if we should escalate to human
    if (!classification.canAutoResolve ||
        classification.sentiment === 'angry' ||
        classification.intent === 'cancellation') {
      return {
        response: await this.generateEscalationResponse(message, customerContext),
        escalated: true,
        intent: classification.intent,
      };
    }

    // Step 3: Retrieve relevant knowledge
    const context = await this.knowledgeBase.query(message);

    // Step 4: Generate response grounded in knowledge base
    const response = await this.generateResponse(message, context, customerContext);

    return { response, escalated: false, intent: classification.intent };
  }

  private async classifyIntent(message: string) {
    const response = await this.client.messages.create({
      model: 'claude-sonnet-4-20250514',
      max_tokens: 256,
      system: `Classify support messages. Return JSON matching:
{ intent, urgency, sentiment, canAutoResolve, escalationReason? }
canAutoResolve = false for: billing disputes, account deletion, legal issues, angry customers.`,
      messages: [{ role: 'user', content: message }],
    });
    const text = response.content[0].type === 'text' ? response.content[0].text : '{}';
    return SupportIntent.parse(JSON.parse(text));
  }

  private async generateResponse(
    message: string, context: string, customer: any
  ): Promise<string> {
    const response = await this.client.messages.create({
      model: 'claude-sonnet-4-20250514',
      max_tokens: 512,
      system: `You are a friendly support agent for a SaaS product.
Use the provided knowledge base context to answer.
Address the customer by name. Be concise but thorough.
If you are not sure about something, say so rather than guessing.
Never make up features or policies not in the context.`,
      messages: [{
        role: 'user',
        content: `Customer: ${customer.name} (${customer.plan} plan)
Knowledge base context: ${context}
Customer message: ${message}`,
      }],
    });
    return response.content[0].type === 'text' ? response.content[0].text : '';
  }

  private async generateEscalationResponse(
    message: string, customer: any
  ): Promise<string> {
    return `Hi ${customer.name}, I want to make sure you get the best help with this. I'm connecting you with a specialist who can assist you directly. They'll have your full context and will be with you shortly.`;
  }
}

Support automation works best as a pipeline: classify intent, check escalation rules, retrieve relevant knowledge, generate response. Always escalate angry customers and sensitive topics (cancellation, billing disputes) to humans. The ROI comes from handling the 70% of queries that are straightforward (password resets, how-to questions, status checks) while routing complex cases with full context to the right specialist.

interface EvalCase {
  input: string;

    name: string;

  }[];

interface EvalResult {
  input: string;
  output: string;
  passed: boolean;
  criteria: { name: string; passed: boolean }[];
  latencyMs: number;
}

async function runEvalSuite(
  systemUnderTest: (input: string) => Promise<string>,
  cases: EvalCase[]
): Promise<{ results: EvalResult[]; passRate: number; avgLatency: number }> {
  const results: EvalResult[] = [];

  for (const testCase of cases) {
    const start = Date.now();
    const output = await systemUnderTest(testCase.input);
    const latencyMs = Date.now() - start;

    const criteriaResults = testCase.criteria.map(c => ({
      name: c.name,
      passed: c.check(output),
    }));

    results.push({
      input: testCase.input,
      output,
      passed: criteriaResults.every(c => c.passed),
      criteria: criteriaResults,
      latencyMs,
    });
  }

  const passRate = results.filter(r => r.passed).length / results.length;
  const avgLatency = results.reduce((s, r) => s + r.latencyMs, 0) / results.length;

  return { results, passRate, avgLatency };
}

Guardrails: Preventing Bad Output

// Output guardrails for production AI
interface GuardrailResult {
  allowed: boolean;
  reason?: string;
  sanitizedOutput?: string;
}

class OutputGuardrails {
  private blockedPatterns = [
    /\b\d{3}-\d{2}-\d{4}\b/,   // SSN pattern
    /\b\d{16}\b/,                // Credit card number
    /password\s*[:=]\s*\S+/i,     // Password exposure
  ];

  private maxOutputLength = 5000;

  check(output: string): GuardrailResult {
    // Check length
    if (output.length > this.maxOutputLength) {
      return {
        allowed: false,
        reason: 'Output exceeds maximum length',
        sanitizedOutput: output.slice(0, this.maxOutputLength),
      };
    }

    // Check for sensitive data patterns
    for (const pattern of this.blockedPatterns) {
      if (pattern.test(output)) {
        return {
          allowed: false,
          reason: `Output contains sensitive data pattern: ${pattern.source}`,
          sanitizedOutput: output.replace(pattern, '[REDACTED]'),
        };
      }
    }

    return { allowed: true };
  }
}

// Wrap your AI function with guardrails
async function safeAICall(
  aiFunction: () => Promise<string>,
  guardrails: OutputGuardrails,
  fallback: string
): Promise<string> {
  try {
    const output = await aiFunction();
    const result = guardrails.check(output);
    if (!result.allowed) {
      console.warn(`Guardrail triggered: ${result.reason}`);
      return result.sanitizedOutput ?? fallback;
    }
    return output;
  } catch (error) {
    console.error('AI call failed:', error);
    return fallback;
  }
}

Human-in-the-Loop Patterns

// Confidence-based routing: AI handles high-confidence, humans handle the rest
async function processWithHumanFallback<T>(
  aiProcess: () => Promise<{ result: T; confidence: number }>,
  humanQueue: Queue<T>,
  confidenceThreshold = 0.85
): Promise<{ result: T; source: 'ai' | 'human_review' }> {
  const { result, confidence } = await aiProcess();

  if (confidence >= confidenceThreshold) {
    return { result, source: 'ai' };
  }

  // Queue for human review
  await humanQueue.enqueue(result);
  const reviewed = await humanQueue.waitForReview();
  return { result: reviewed, source: 'human_review' };
}

Key Takeaway

Production AI requires three layers of defense: evaluation (measuring quality with automated test suites), guardrails (preventing harmful output in real-time), and human-in-the-loop (routing low-confidence cases to humans). Build evaluation suites before deploying, run them on every model change, and set confidence thresholds based on the cost of errors in your specific domain. Medical or financial AI needs higher thresholds than marketing copy.

    const cost = (inputTokens * pricing.inputPer1M + outputTokens * pricing.outputPer1M) / 1_000_000;

      totalCost: `$${this.totalCost.toFixed(4)}`,
      totalCalls: this.calls.length,
      avgCostPerCall: `$${(this.totalCost / this.calls.length).toFixed(4)}`,
      byModel: Object.groupBy(this.calls, c => c.model),
    };
  }

function compressContext(context: string, maxChars = 3000): string {
  if (context.length <= maxChars) return context;
  // Remove redundant whitespace, truncate at sentence boundary
  const compressed = context.replace(/\s+/g, ' ').trim();
  const truncated = compressed.slice(0, maxChars);
  const lastPeriod = truncated.lastIndexOf('.');
  return lastPeriod > maxChars * 0.8 ? truncated.slice(0, lastPeriod + 1) : truncated;
}
